# 后端验证记录

在 Docker Desktop 的 Linux ARM64 容器运行 Node.js 和 OpenCode CLI 1.1.36，通过真实模型网关测试 HTTP API。材料使用虚构会议摘录，凭据通过运行时环境注入。另用独立 Compose 项目确认镜像构建、卷挂载和健康检查。

## 真实模型联调

- 建立会话 A，生成并下载 Python 文件，校验其中的测试标记。SSE 收到排队、运行、工具、文本和成功事件。
- 建立会话 B，上传会议材料，生成并下载 Markdown 行动清单，核对负责人。会话 B 下载会话 A 的产物返回 404。
- 重启容器后，两个会话仍存在。会话 A 的 OpenCode 会话 ID 保持一致，追问正确复述上轮标记。
- 用 SSE 的最后一个事件 ID 重连，已接收的事件没有重复发送。路径穿越请求返回 404。

关闭标题生成后的一次联调共向上游发出 11 次请求。代码任务、材料任务和追问分别发出 4、6、1 次请求。该轮上游实际返回的 token 统计分别为 20,765、31,637、5,461。具体用量随模型工具步骤变化。完成流完整性校验后，重新构建容器并验证纯文本任务成功，模型请求数为 1。

首次联调曾遇到上游 429。任务以 `MODEL_RATE_LIMITED` 失败，并保留已记录用量。随后精简了工具与系统提示，加入出站间隔，关闭了 CLI 的逐消息标题生成。

## 本地自动化检查

`npm test` 的 6 项检查在本机和 Node.js 24 容器中均通过，覆盖分块中文 JSONL、任务冲突与中断恢复、出站额度和用量持久化、文件路径边界、取消和空输出失败，以及上游限流和截断流处理。本地测试使用模拟上游和 CLI，真实模型结果在上节单独记录。
