# 云端 Agent 助手工作台设计

## 1. 目标与验收范围

应用面向一位本机用户。用户在浏览器创建会话、发送任务、上传材料和下载成果。Agent 执行代码和文件任务时，应用展示来自 CLI 的真实事件。用户切换会话或关闭浏览器后，可以重新打开工作台查看历史与运行结果，并沿用原会话继续交流。

首版交付一个 Docker 启动入口。宿主机通过本地浏览器访问。一次执行一个任务，多个会话可独立保存和切换。多人登录、远程部署和并行执行留待后续版本。

| 用户操作 | 验收结果 |
| --- | --- |
| 创建会话并提交任务 | 任务进入队列，后台调用真实 OpenCode CLI |
| 查看运行过程 | 页面依次展示排队、运行、工具摘要和最终结果 |
| 上传材料并交给 Agent | Agent 在当前会话工作目录读到材料，生成结果可下载 |
| 切换会话或刷新页面 | 恢复该会话的历史、任务状态、文件及最新事件 |
| 在原会话追问 | 后端使用该会话保存的 CLI 会话 ID，Agent 沿用上轮上下文 |
| 运行失败、超时或被取消 | 显示实际结果，保留已产生的事件和文件 |

## 2. 技术选型与运行边界

- **前端**采用 React 和 Vite。生产镜像由 Node.js 服务同源提供静态文件及 API。浏览器只访问工作台接口。
- **后端**采用 Node.js、Express 和 SQLite。用 SQLite 持久化会话、消息、任务和事件。用 Node 的子进程接口启动 CLI 并读取标准输出。
- **Agent**采用 OpenCode CLI。开发先固定本机实测的 `1.1.36`，通过 OpenAI 兼容 provider 接入 Chat Completions。模型、接口及凭据从服务端配置读取。
- **容器**采用单镜像和一个命名数据卷。进程以非 root 用户运行，Compose 默认将端口绑定到 `127.0.0.1`。镜像内包含 CLI 和完成演示所需的命令行工具。

本机已经用平台模型验证 OpenCode 的文件写入、JSON 工具事件和会话续接。模型接口测试还确认 Chat Completions 和 Responses 均能返回流式工具调用。本机验证与容器验收分开记录。首个实现步骤是在容器中重跑两轮测试，再接入页面。

## 3. 会话页面与交互

- 左栏显示会话列表、任务状态和新建入口。
- 中栏显示消息历史、任务事件、输入框和取消操作。工具事件默认只显示工具名称、阶段和简短结果。
- 右栏展示上传材料和生成文件。列表提供相对路径、大小及下载。执行期间文件列表可按任务事件刷新，任务结束时再校准。
- 排队、运行、成功、失败、取消、超时和中断都有明确文案。进度采用实际阶段和可见事件。空会话与空文件区分别提供上传或发任务的入口。

浏览器初始化时获取会话详情、活跃任务和事件游标。随后订阅任务流。连接中断时带上最后收到的事件编号重连。切换会话会关闭旧订阅，任务进程继续由后端管理。

## 4. 持久化模型

| 实体 | 主要字段及职责 |
| --- | --- |
| `sessions` | 应用会话 ID、标题、CLI 会话 ID、创建时间、更新时间 |
| `messages` | 消息 ID、会话 ID、任务 ID、角色、正文、时间 |
| `runs` | 任务 ID、会话 ID、用户消息 ID、状态、提交与完成时间、错误类型、退出码 |
| `run_events` | 任务 ID、递增事件编号、业务事件类型、有限长度的事件负载、时间 |
| `uploads` | 上传 ID、会话 ID、原文件名、实际相对路径、大小、时间 |

会话目录按应用生成的 ID 分配。Docker 重建后，挂载同一命名卷可以恢复数据。

```text
/data/
  workbench.sqlite
  sessions/
    <session-id>/
      open-code-data/
      workspace/
        inputs/
        outputs/
```

OpenCode 的数据目录独立于可下载文件目录。上传写入 `inputs/`，生成成果优先放在 `outputs/`，代码项目也可留在工作目录的普通子目录。浏览器文件列表从当前工作目录产生，覆盖代码与报告。可执行产物保留原格式，以下载方式提供。

提交消息时，在同一事务写入用户消息、排队任务和首条事件。对同一会话的活跃任务使用唯一约束，防止双击或并发请求创建两次执行。各会话的任务按提交顺序调度。SQLite 使用 WAL。历史与文件列表按页返回，任务事件按编号重放。

## 5. 从提交到继续交流

1. 浏览器提交消息。后端验证输入与会话状态，写入待执行任务后返回 HTTP 202 和任务 ID。
2. 调度器领取队首任务。用受控参数数组调用子进程。首次执行使用 `opencode run --format json`，续接增加 `--session <cliSessionId>`。工作目录由服务端选定。
3. 后端逐行解析 JSONL。记录工具阶段、文本和错误等事件。首次取得 CLI 会话 ID 时立即保存，后续严格使用该 ID。标准错误只保留限长且脱敏的诊断。
4. SSE 从持久化事件读取并以事件编号续传。运行完成时写入最终消息和终态，再发送终态事件。
5. 下一轮消息再次入队，在同一工作目录执行。文件和 CLI 上下文均随会话保留。

退出码、CLI 错误和输出共同决定终态。退出码为零且收到有效结果，才能标记成功。工具事件可能包含一次失败后继续的过程，页面展示对应事件，最终状态由整轮结果决定。

```text
queued -> running -> succeeded | failed | cancelled | timed_out | interrupted
queued -> cancelled
```

- 取消排队任务直接更新状态。取消运行中任务向受控进程组发出终止信号，等待退出后写终态，超出宽限时间时强制结束。
- 服务启动时将遗留的运行中任务标为中断。已排队的任务恢复调度。已有副作用的执行由用户决定是否继续。
- API 认证失败、限流、超时、非预期退出和无有效输出分别分类。表面成功但缺少有效输出时，报告失败并保留已有证据。

## 6. 应用接口

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/sessions` | 分页列出会话 |
| `POST /api/sessions` | 创建会话，返回 201 |
| `GET /api/sessions/:id` | 获取会话详情、消息分页和活跃任务 |
| `POST /api/sessions/:id/messages` | 接纳任务，返回 202。会话已有活跃任务时返回 409 |
| `GET /api/runs/:id/events` | 按游标回放并订阅 SSE，支持 `Last-Event-ID` |
| `POST /api/runs/:id/cancel` | 请求取消，响应包含当前状态 |
| `GET /api/sessions/:id/files` | 分页列出当前工作目录的材料和成果 |
| `POST /api/sessions/:id/files` | 增量写入上传材料 |
| `GET /api/sessions/:id/files/download?path=…` | 以附件下载当前工作目录内的文件 |
| `GET /api/health` | 检查进程能访问持久化数据 |

API 错误使用稳定的 `code`、可读消息和请求 ID。限制单条事件、上传和浏览器回放批次的大小。初始上限为单文件 20 MiB、每页 50 项和单轮 5 分钟，按容器实测评估。上传失败时清理临时文件。运行中的文件可能尚未写完，界面显示任务状态。

## 7. 配置、文件边界和已知限制

| 环境变量 | 用途 |
| --- | --- |
| `AGENT_API_BASE_URL` | 模型网关的 API 基地址 |
| `AGENT_API_KEY` | 模型网关凭据，由服务端环境提供 |
| `AGENT_MODEL` | 网关返回的模型 ID |
| `DATA_DIR` | 容器持久化目录，默认 `/data` |
| `PORT` | 容器内监听端口，默认 `3000` |

- 凭据通过服务端环境使用。浏览器响应、日志、Docker 构建参数和 Git 只包含公开配置或占位值。启动时检查必需配置，健康接口避免额外消耗模型调用。
- 调用 CLI 时显式构造参数，用户消息作为单一参数传递。上传路径由服务端生成，下载解析实际路径并核对目录边界，禁止通过符号链接或路径穿越读取其他目录。静态文件和下载分开处理。
- 服务拒绝来自其他站点的写请求。容器只挂载应用数据卷，避免接入宿主机目录或 Docker socket。OpenCode 的工作目录策略提供会话级操作范围。单容器同用户执行提供的是单用户开发环境，多个会话之间缺少操作系统级沙箱，使用时限于可信任务和材料。
- 浏览器关闭时后台任务继续。容器停止时不能保证运行中的进程继续。SQLite、文件和 CLI 上下文依赖数据卷保留。
- 报告演示使用 Markdown，表格使用 CSV。其他文件格式的语义读取取决于镜像工具和模型能力，支持范围以实际验收记录为准。

## 8. 实现顺序与交付验收

1. **验证运行底座**。启动 Docker，构建带固定 OpenCode 版本的镜像。用临时 API 测试写文件、JSON 事件和续接。确认卷内数据可恢复。
2. **打通后端**。实现会话、持久队列、CLI 子进程、事件流及文件上传下载。验证请求接纳、续接、失败和中断状态。
3. **接入浏览器页面**。从真实数据恢复会话与文件。完成流式呈现、切换会话、刷新和取消交互。
4. **留出约 25 分钟验收交付**。从干净检出构建。跑两套演示与关键失败场景。记录 Docker 命令、实际成果、浏览器截图和对应提交。更新 README，并确认远端默认分支上的提交与验收版本一致。

### 代码开发演示

新建会话 A。让 Agent 生成一个汇总销售 CSV 的 Python 脚本和测试。观察工具事件，验证测试通过并下载源文件。追问增加按月份筛选，再验证筛选结果和测试。

### 日常工作演示

新建会话 B，上传虚构会议纪要。让 Agent 输出 Markdown 行动清单，包含负责人、截止日期和待确认项。下载报告并与原材料核对。刷新后切回会话 A，再进行一次提问，确认上下文和两个会话的文件仍可访问。

### 异常与证据

验证重复提交、取消运行、无效 API 凭据、页面断线恢复、容器重启及越界文件访问。保存脱敏日志和运行证据，标明每项的实际结果。README 记录启动、配置、使用和已知限制。交卷使用公开 GitHub 仓库链接，以平台正式交卷时记录的提交为准。
